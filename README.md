# INTERES WORLD — автопостинг без Make

Одна история → 4 языка (FR, IT, EN, NL) → 4 статьи на interes-world.com → фото и текст на 34 страницах Facebook → ссылка на статью в первом комментарии. Работает в облаке GitHub по расписанию, компьютер может быть выключен.

## Как это работает

```
Новая история (ваш пост с фото на любой из 34 страниц ИЛИ ссылка в очереди)
   │  за ~3 часа до выхода
   ▼
Claude пишет: заголовок · текст для Facebook · статью 700–800 слов — на FR / IT / EN / NL
   ▼
WordPress: фото в медиатеку + 4 статьи, запланированные на час публикации
   ▼
Facebook: 33–34 отложенных поста с фото (Facebook сам выпускает их ровно в заданную минуту)
   │  через 7 минут после выхода (и повторно через 37 минут)
   ▼
Первый комментарий на каждой странице: https://peakproductions.co/?p=ID (до 09.11.2026 — interes-world.com)
```

## Надёжность

- **Без дублей.** Каждый шаг записывается в `state/state.json` и сохраняется в репозиторий по ходу работы. Кроме того, перед каждым созданием система проверяет саму площадку. Статья ищется по постоянному адресу (slug), пост — среди отложенных и опубликованных постов страницы, комментарий — среди комментариев. Поэтому даже повторный запуск или потеря состояния не создают дублей.
- **Ошибка одной страницы не останавливает остальные.** Токены страниц нигде не выводятся в журналах.
- **Повтор только неудавшегося.** Если не вышло на одной странице, повторяется только она (до 4 попыток). Остальные 33 не трогаются.
- **Результаты сохраняются.** Тексты лежат в `content/`, журнал — в `logs/`, отчёты — в `previews/`, сводка видна на вкладке Actions. При окончательной ошибке GitHub присылает письмо.
- **Картинки не пропадают.** Фото загружается в медиатеку сайта, а не ссылается на временный адрес Facebook, как было в Make.
- **Один пост — одна страница-источник.** История не публикуется повторно на странице, где она уже есть (`skip_source_page`).

## Откуда берутся истории

1. **Авто (по умолчанию).** Новый пост с фото и текстом от 300 символов, опубликованный вручную на любой из 34 страниц, система берёт сама. Ссылки вставлять не нужно. «Новыми» считаются посты, опубликованные после подключения Facebook (этап 4). Старые посты, всё опубликованное Make и посты, под которыми уже есть ссылка `interes-world.com/?p=`, не берутся.
2. **Очередь `queue/links.txt`.** Одна ссылка на строку. Удобно, если нужна конкретная история.
3. **Старая таблица `FB_QUEUE`.** Включается в `settings.yaml` (`google_sheet.enabled: true`), если таблица открыта по ссылке для чтения.

Ограничение Facebook: посты чужих страниц через API читать нельзя без отдельной проверки приложения Meta («Page Public Content Access»). Поэтому источником могут быть только ваши страницы.

## Кнопки на вкладке Actions

| Workflow | Что делает | Публикует? |
|---|---|---|
| 0 · Проверка кода | тесты и сухой прогон на поддельных сервисах | нет |
| 1 · Проверка подключений | Facebook (34 страницы), WordPress, Claude, источник историй | нет |
| 2 · Подключить Facebook | получает бессрочные токены страниц и хранит их зашифрованными | нет |
| 3 · Закрытый тест | тексты на 4 языка + черновик на сайте + отложенный пост (оба сразу удаляются) | нет |
| 4 · Публичный тест | 1 статья + 1 пост на 1 странице + комментарий (нужно ввести PUBLISH) | да, 1 пост |
| 5 · Автопостинг по расписанию | работа по расписанию | да |
| 6 · Включить или выключить расписание | on / off | — |

## Секреты (GitHub → Settings → Secrets and variables → Actions)

| Секрет | Откуда |
|---|---|
| `FB_APP_ID`, `FB_APP_SECRET` | developers.facebook.com → ваше приложение → Settings → Basic |
| `FB_USER_TOKEN` | Graph API Explorer → Generate Access Token (официальное окно входа Facebook). Нужен один раз, потом его можно удалить |
| `WP_USER`, `WP_APP_PASSWORD` | peakproductions.co/wp-admin (с 09.11.2026; раньше interes-world.com) → Users → Profile → Application Passwords |
| `CLAUDE_CODE_OAUTH_TOKEN` | на компьютере: `claude setup-token` (подписка Max, токен действует 1 год) |
| `ANTHROPIC_API_KEY` | необязательно, резерв: platform.claude.com → API keys |

## Настройки (`config/settings.yaml`)

- `slots` — часы публикаций по Еревану. После изменения нужно обновить расписание в `.github/workflows/autopost.yml` командой `python -m autopost render-workflow` (это сделает Claude).
- `schedule_enabled` — включено ли расписание (или кнопка 6).
- `claude.model` — модель для текстов (по умолчанию `claude-sonnet-5-5`).

## Расход минут GitHub (оценка)

18 запусков в день: подготовка, повтор подготовки, комментарии и повтор комментариев на каждый слот, плюс два догоняющих запуска после последнего слота. Лёгкий запуск длится меньше минуты, подготовка истории — около 3 минут. Итого примерно 1 000–1 300 минут в месяц при бесплатном лимите 2 000 для закрытого репозитория.

python -m autopost status                 # состояние слотов
